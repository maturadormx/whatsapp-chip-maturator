O QUE FOI IMPLEMENTADO

## 1. Health checks

Arquivo:
- `server/_core/index.ts`

Endpoints:
- `/live`
- `/ready`
- `/health`

Comportamento:
- `/live` responde prontidão básica do processo
- `/ready` continua usando `observationRuntime.checkReady()`
- `/health` agrega o status de runtime em payload operacional

## 2. Dockerfile

Arquivo:
- `Dockerfile`

Estratégia:
- build em estágio separado
- runtime com Node 22 Alpine
- `npm run start`

Objetivo:
- permitir que a app participe da stack operacional via compose

## 3. Compose operacional

Arquivo:
- `docker-compose.operations.yml`

Serviços definidos:
- `app`
- `redis`
- `prometheus`
- `alertmanager`
- `grafana`

Objetivo:
- subir uma stack local completa de observabilidade e operação

## 4. Prometheus

Arquivos:
- `monitoring/prometheus/prometheus.yml`
- `monitoring/prometheus/rules/whatsapp-chip-maturator.yml`

Scrapes:
- app `/internal/metrics`
- prometheus
- alertmanager

Alertas implementados:
- `WorkerStopped`
- `QueueGrowing`
- `DlqHasJobs`
- `PipelineFailureRateHigh`
- `SchedulerStopped`

## 5. Alertmanager

Arquivo:
- `monitoring/alertmanager/alertmanager.yml`

Configuração:
- receiver inicial `blackhole`

Objetivo:
- permitir wiring de alertas já na stack, sem bloquear por integração externa

## 6. Grafana

Provisionamento:
- datasource Prometheus automático
- provider automático de dashboards

Dashboards criados:
- Queue
- Worker
- Pipeline
- Scheduler
- DLQ

Objetivo:
- fornecer a primeira camada operacional visual sem configuração manual

## 7. Workflow de CI

Arquivo:
- `.github/workflows/ci.yml`

Pipeline:
- checkout
- setup Node 22
- `npm install`
- `npx tsc --noEmit`
- `npm test`
- `npm run build`
- `python -m py_compile auditoria.py`

Objetivo:
- transformar a validação já usada localmente em verificação automática

## 8. Runbook operacional

Arquivo:
- `docs/runbooks/operational-observability.md`

Conteúdo:
- URLs dos serviços
- subida da stack
- validação inicial
- leitura dos alertas
- incidentes comuns
- uso do auditor da Sprint 0
