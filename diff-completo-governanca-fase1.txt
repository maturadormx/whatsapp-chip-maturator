DIFF COMPLETO — GOVERNANÇA E FECHAMENTO FORMAL DA FASE 1
Projeto: whatsapp-chip-maturator
Data: 2026-07-20

OBJETIVO DA RODADA
Executar os itens normativos pedidos para o fechamento formal da Fase 1:

- governança do Marco 2 / Fase 1
- invariantes arquiteturais
- máquina de estados documentada
- definition of done
- processo de release e política de baseline
- changelog e release notes
- manutenção da evidência técnica com testes e build

ENQUADRAMENTO
Esta rodada não abriu a Fase 2 nem adicionou novo domínio funcional. Ela consolida o gate documental e de release da Fase 1, mantendo o alinhamento entre:

- implementação
- validação
- baseline
- liberação formal da próxima fase

VALIDAÇÃO FINAL
- `pnpm test` -> `70/70` testes passando
- `24` arquivos de teste
- `pnpm build` -> `OK`

4. `docs/architecture/invariants.md`
O que foi criado:

- invariantes de budget
- invariantes de retry
- invariantes da integração da Fase 1

- `executionId + attempt` único

- reserva termina em `COMMITTED` ou `RELEASED`

Efeito prático:
- o projeto agora tem um ponto único para ler os invariantes do núcleo operacional

O QUE FOI PRESERVADO DE PROPÓSITO

Não foi feito:
- criação de `git tag` real
- abertura da Fase 2
- implementação de `MessageGateway`
- `MockGateway`
- `Clock`
- `Inbound`

Motivo:
- a tag real deve apontar para um commit reproduzível
- neste ambiente existem mudanças ainda não formalizadas como merge/CI de baseline
- criar tag agora seria tecnicamente enganoso

Portanto, o que ficou pronto foi:
- toda a documentação e o processo para a tag
- o estado “pronto para tag”

GANHO DE GOVERNANÇA
Antes:
- a fase estava tecnicamente validada
- mas o processo formal ainda estava distribuído entre conversa, matriz e artefatos soltos

Depois:
- existe um pacote normativo completo dentro do repositório
- existe DoD
- existe processo de release
- existe política de baseline
- existe changelog
- existe release notes
- existe documento principal de governança da fase

GANHO ARQUITETURAL
Esta rodada não muda o domínio, mas reduz risco arquitetural de forma relevante porque:

- documenta invariantes
- congela a semântica do núcleo
- define a máquina de estados como baseline
- evita começar a Fase 2 sem critério formal
