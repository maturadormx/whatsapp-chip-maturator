MUDANÇAS PRINCIPAIS

1. Logger estruturado

Antes:
- `ObservationPipeline` ainda tinha `console.log` implícito como fallback

Depois:
- `LoggerPort` foi introduzido
- `DevLogger` implementa:
  - `debug`
  - `info`
  - `warn`
  - `error`
- o pipeline agora emite eventos estruturados, como:
  - `pipeline.started`
  - `observation.saved`
  - `fact.generated`
  - `rule.evaluated`
  - `plan.created`
  - `plan.executed`
  - `pipeline.completed`

2. RuleEngine mínimo

Antes:
- `ExecutionPlan` era sempre um plano vazio / neutro

Depois:
- `RuleEnginePort.evaluate(fact)` retorna `ExecutionAction[]`
- `DefaultRuleEngine` usa uma lista de regras
- `CriticalAlertRule` adiciona uma ação:
  - `alert`
  quando `fact.data.severity === "critical"`

3. ExecutionPlan com ações reais

Antes:
- `ExecutionPlan` tinha:
  - `action: "noop"`

Depois:
- `ExecutionPlan` passa a ter:
  - `actions: ExecutionAction[]`
- `ExecutionPlanFactory.fromFact(fact, actions)` cria plano com ações concretas

4. Event Store tipado

Antes:
- não havia histórico mínimo do pipeline interno

Depois:
- `EventStorePort.append(stream, event)`
- `EventStorePort.get(stream)`
- `MemoryEventStore` como implementação inicial
- o pipeline grava envelopes tipados, não objetos crus

Eventos gravados:
- stream `observation`:
  - `ObservationSaved`
- stream `fact`:
  - `FactGenerated`

ORDEM FINAL DO PIPELINE

```text
Observation
→ logger.debug(pipeline.started)
→ repository.save(observation)
→ logger.info(observation.saved)
→ eventStore.append("observation", ObservationSaved)
→ FactFactory.create(observation)
→ logger.info(fact.generated)
→ eventStore.append("fact", FactGenerated)
→ ruleEngine.evaluate(fact)
→ logger.debug(rule.evaluated)
→ ExecutionPlanFactory.fromFact(fact, actions)
→ logger.debug(plan.created)
→ executionService.execute(plan)
→ logger.info(plan.executed)
→ logger.debug(pipeline.completed)
```
