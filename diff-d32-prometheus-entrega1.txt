ESCOPO IMPLEMENTADO

## 1. Dependência Prometheus

Arquivo:
- `package.json`

Dependência adicionada:
- `prom-client`

## 2. Registry singleton

Arquivos:
- `server/metrics/PrometheusRegistry.ts`
- `server/metrics/index.ts`

O que faz:
- cria um `Registry` singleton
- registra `collectDefaultMetrics()`
- expõe `initMetrics()` idempotente
- expõe `getRegistry()`

Detalhe importante:
- `collectDefaultMetrics()` fica no nível do módulo, não dentro de `initMetrics()`
- isso evita duplicação de métricas por inicialização repetida

## 3. Endpoint interno de métricas

Arquivo:
- `server/routes/internal/metrics.ts`

Rota criada:
- `GET /internal/metrics`

Comportamento:
- define `Content-Type` com `registry.contentType`
- retorna `await registry.metrics()`
- responde no formato Prometheus exposition

## 4. Bootstrap

Arquivo:
- `server/_core/index.ts`

Mudanças:
- `initMetrics()` agora é chamado no bootstrap
- `app.use("/internal", internalMetricsRouter)` foi registrado

Resultado:
- o endpoint interno entra no servidor principal
- a inicialização é segura para chamadas repetidas

## 5. Testes

Arquivo:
- `server/routes/internal/metrics.test.ts`

Casos cobertos:

1. `GET /internal/metrics`
- retorna `200`
- retorna `Content-Type` texto Prometheus
- contém `# HELP`
- contém `# TYPE`

2. Singleton
- `getRegistry()` retorna a mesma instância de `registry`
