DIFF — ARQUITETURA VISUAL E ESTRUTURAL COMPLETA
Projeto: whatsapp-chip-maturator
Data: 2026-07-22

1. Objetivo

Este diff documenta a parte visual inteira do sistema:

- arquitetura estrutural do frontend
- rotas e superfícies principais
- navegação global
- sidebars
- abas, âncoras e modos de tela
- padrões visuais reutilizados
- diferenças entre sistema 1, sistema 2, central admin e áreas utilitárias

2. Estrutura base do frontend

Entradas principais:
- `client/index.html`
- `client/src/main.tsx`
- `client/src/App.tsx`

Camadas estruturais:
- bootstrap React via `main.tsx`
- roteamento com `wouter`
- providers globais:
  - `ThemeProvider`
  - `TooltipProvider`
  - `Toaster`
  - `ErrorBoundary`

Comportamento global:
- `Navbar` fica visível em todo o app
- exceção: `/login`
- `EntryRoute` redireciona automaticamente conforme role
- telas administrativas usam `AdminOnly`

3. Arquitetura de navegação

3.1) Rotas principais

Mapa de rotas em `client/src/App.tsx`:

- `/` → entrada dinâmica por role
- `/workspace` → área do usuário comum
- `/admin-systems` → central administrativa dos dois sistemas
- `/system-demo` → demo institucional/ecossistema
- `/dashboard` e `/maturation` → sistema 1 / maturação
- `/bulk-dispatch` e `/marketing` → sistema 2 / marketing
- `/reports` → relatórios
- `/operations` → operação
- `/runtime` → runtime
- `/control-center` + subrotas → painel estrutural central
- `/plans` → planos
- `/profile` → perfil
- `/connect-chip` → conexão de chip
- `/logs` → logs
- `/profiles` → perfis
- `/admin` → dashboard administrativo
- `/login` → autenticação
- `/404` → não encontrado

3.2) Guardas de acesso

Diferença estrutural importante:

- usuário comum:
  - `workspace`
  - `plans`
  - `profile`
- admin:
  - central completa
  - sistemas operacionais
  - relatórios
  - runtime
  - painel admin
  - control center

5. Sidebars e navegação lateral

Há dois modelos distintos de sidebar.

5.1) `DashboardLayout`

Arquivo:
- `client/src/components/DashboardLayout.tsx`

Características:
- sidebar colapsável por ícone
- largura redimensionável
- estado persistido em `localStorage`
- modo mobile com `SidebarTrigger`
- menu genérico de navegação

Função estrutural:
- é um layout genérico de dashboard
- menos conectado à narrativa comercial dos dois sistemas
- mais próximo de shell administrativo clássico

5.2) `SystemSidebar`

Arquivo:
- `client/src/components/SystemSidebar.tsx`

Este é o componente visual mais importante da arquitetura atual dos sistemas.

Dois perfis:

- `maturation`
- `marketing`

Sistema 1 / Maturação:
- `Central admin`
- `Visão geral`
- `Conectar chips`
- `Perfis`
- `Operação`
- `Logs`
- `Relatórios`

Sistema 2 / Marketing:
- `Central admin`
- `Campanhas`
- `Fila e agenda`
- `Análises`
- `Lista de bloqueio`
- `Relatórios`

Diferença estrutural:
- sistema 1 usa acento emerald
- sistema 2 usa acento fuchsia
- a sidebar já funciona como separador mental entre os produtos

8. Abas, modos e subnavegação

8.1) Abas identificadas diretamente

Em `AdminDashboard.tsx`:
- estado `activeTab = "overview"`
- portanto há arquitetura em tabs internas

Em outras páginas:
- há uso recorrente de `TabsList`, `TabsTrigger`, `TabsContent` no frontend
- isso confirma múltiplas superfícies com navegação interna em tabs

8.2) Subrotas estruturais

`ControlCenter` é roteado por subrotas.
Na prática isso equivale a abas estruturais dirigidas por URL:

- visão geral
- fleet
- workers
- reconciliation
- admin
- security
- chip detalhado

8.3) Âncoras internas

`BulkDispatch` possui navegação com hash:

- `#fila`
- `#analytics`
- `#blacklist`

Isso indica scroll/navigation intra-page orientada por seções.

12. Conclusão do diff visual

A arquitetura visual do produto não é monolítica.
Ela foi organizada em cinco superfícies diferentes:

- portal de entrada
- sistema 1
- sistema 2
- camada administrativa
- camada estrutural/técnica

O desenho geral já mostra uma intenção forte de produto:

- separar “base operacional” de “execução comercial”
- manter uma central única de entrada
- dar à administração um painel próprio
- reservar ao runtime/control center uma camada mais técnica e estrutural
