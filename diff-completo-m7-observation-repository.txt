MUDANÇA PRINCIPAL NO PIPELINE

Antes:
- pipeline gerava Fact e executava side-effect (`onFactGenerated`) sem persistência

Depois:
1. `repository.save(observation)`
2. `createFact(observation)`
3. `onFactGenerated(fact)`

Garantias documentadas em `ObservationPipelinePort`:
- persistência ocorre antes de qualquer transformação
- Fact só existe se persistência tiver sucesso
- nenhum side-effect acontece antes do save
- erro de persistência é propagado

POLÍTICA DE RETORNO HTTP

- sucesso do pipeline -> `202 Accepted`
- falha na persistência -> `500 Internal Server Error`

TESTES ADICIONADOS/REFORÇADOS

Pipeline:
- ordem: `save()` ocorre antes de `createFact()` usando `invocationCallOrder`
- falha: `save()` falha -> não chama `createFact()` nem `onFactGenerated()`

Inbound:
- endpoint retorna `500` se o pipeline falhar

VEREDITO
O pipeline agora possui o primeiro efeito colateral real (persistência) com disciplina explícita: `Observation` é registro canônico e é persistida antes de qualquer derivação. Isso prepara o terreno para replay/auditoria e permite evoluir para `ExecutionService` consumindo `Fact` (M8) sem que o HTTP precise conhecer o domínio interno.
