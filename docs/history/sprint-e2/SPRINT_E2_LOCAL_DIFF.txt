3. Evidência importante descoberta

Durante a rodada apareceu um problema real ao tentar ligar migrações automáticas no startup:

- o container entrava em loop de restart
- a cadeia `db:push` com `drizzle-kit generate && migrate` não é apropriada para bootstrap repetível
- o journal de migração em `drizzle/meta/_journal.json` estava atrasado em relação aos SQLs presentes

Diagnóstico operacional:
- usar `RUN_MIGRATIONS_ON_START=true` neste estágio introduz instabilidade desnecessária na certificação local
- a migração deve ser explícita, não automática

4. Correções aplicadas

4.1) Migração fora do startup
- removido `RUN_MIGRATIONS_ON_START` dos compose files
- `Dockerfile` voltou a subir com `npm run start`
- criado `scripts/migrate-local.ps1` para execução manual/ explícita

4.2) db:push corrigido
- `package.json`
  - `db:push` passou a usar:
    - `drizzle-kit --config drizzle.config.ts generate`
    - `drizzle-kit --config drizzle.config.ts migrate`

4.3) Runner preparado
- `Dockerfile` copia:
  - `drizzle/`
  - `drizzle.config.ts`
